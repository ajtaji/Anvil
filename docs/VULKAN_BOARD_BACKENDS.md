# Vulkan board backend capabilities

The shared Vulkan object and command layer is board-neutral. Its backend seam is declared in `Anvil/Graphics/Vulkan/vk_foundation.pbi`: capabilities, device preparation and limits, memory/image planning, validated transfer submission, completion polling, and closed draw/pipeline records. Portable code passes resolved records rather than board handles or packet formats.

Backend choice is **static at build time**. Exactly one backend file is included; none, test, software, and V3D implementations share the seam. There is no runtime registration or dynamic backend loading. Capability bits describe the linked backend, so device, clear, GPU, draw, source-over blend, and draw-list support can be reported independently.

## Bounded image readback

The Pi 4 backend supports full-image and bounded partial level-zero optimal BGRA8 readback into a transfer-destination buffer through guarded 2D DMA. The 2026-09-27 37×13 whole-image diagnostic checked all 481 texels, untouched padding and 40 DMA operations. R2 checked a 4×4-aligned 16-texel partial region with 16 padding words, 32 guard words and one DMA; an unaligned request returned `-20005`. R3 checked a padded `(32,8)` `5×5` region ending at the right and bottom edges of a 37×13 image: all 25 texels matched, 15 padding words and 32 guard words remained intact, with four DMA operations. A same-sized `(28,4)` non-edge request returned `-20005` without extra work. Source offsets must align to 4×4 utiles; a short width or height is accepted only when it reaches that respective image edge. Mips, layers, format conversion, and other edge cases remain unsupported. This is Pi 4-specific evidence, not support on other backends; see `docs/evidence/vulkan-optimal-edge-tail-pi4-20260930/README.md`.

## Bounded optimal-to-linear image copy

The shared `vkCmdCopyImage` path now records a bounded partial region from a distinct, equal-size level-zero BGRA8 optimal source into a linear destination. Source offsets must align to 4×4 utiles. Width and height must be multiples of four unless the respective extent reaches the source image's right or bottom edge. Destination offsets are texel coordinates and must keep the copied rectangle in bounds; source and destination allocations must be disjoint. Invalid regions are refused during recording or whole-stream preflight before DMA work. The Pi 4 backend lowers accepted regions through guarded DMA, with no CPU pixel copy. The 2026-09-30 Pi 4 proof copied all 25 texels of a `(32,8)` `5×5` region from a 37×13 image, preserved 456 other texels and 32 guard words, and advanced DMA 0→4, TFU 0→1 and backend jobs 1→2. The 148-byte destination pitch had no padding words; a same-sized non-edge tail returned `-20005` without further transfer work. This is not a capability claim for other board backends; see `docs/evidence/vulkan-partial-optimal-linear-pi4-20260930/README.md`. Mips, layers and format conversion remain unsupported.

## Bounded partial linear-to-optimal image copy

The shared `vkCmdCopyImage` path accepts one partial region per command buffer between distinct, equal-size level-zero BGRA8 images. Linear source offsets may be any in-bounds texel coordinates; validation and submission use the actual source pitch and preflight the row spans. The optimal destination offsets and extent must align to 4×4 utiles, with a maximum of 256 utiles. The bound allocations must be disjoint. Pi 4 lowers this shape through guarded DMA under a dedicated linear-to-tiled rectangle capability; the complete-image TFU path remains unchanged. The 2026-09-30 Pi 4 proof copied 16 exact texels, preserved 240 untouched texels and matched all 256 source texels; 64 padding and 96 guard checks passed. TFU stayed at 1, DMA advanced 0→1 and backend jobs 1→2; a later readback advanced DMA 1→17. A misaligned destination returned `-20005` before readback. MMU, OOM and native fault counts were zero, with one intentional validation fault. See `docs/evidence/vulkan-partial-linear-optimal-pi4-20260930/README.md`. Other board backends do not advertise this capability.

## Bounded partial buffer-to-optimal image upload

The shared `vkCmdCopyBufferToImage` path implements one partial region per command buffer from a transfer-source buffer into a distinct, bound optimal BGRA8 image. The Pi 4 backend requires a 64-byte-aligned `bufferOffset`; `bufferRowLength` may be tight (`0`) or padded, and `bufferImageHeight` must be zero or at least the copied height. Source bounds use the exact accessed span `(height - 1) * pitch + width * 4`, excluding unused padding after the last row. Destination XY offsets and extents align to 4×4 utiles, with a maximum of 256 utiles; allocations must be disjoint. The shared stream is preflighted before work, and Pi 4 lowers accepted regions through guarded DMA behind the dedicated `BUFFER_TO_TILED_RECT_COPY` capability. The complete-image TFU upload is unchanged. The 2026-09-30 Pi 4 proof replaced 16 destination texels and preserved 240 others; it checked 272 source words including 16 padding words, 64 readback padding and 96 guard checks. TFU stayed at 1, DMA advanced 0→1, and jobs advanced 1→2; a later readback advanced DMA 1→17. Destination `(2,8)` returned `-20005` before readback. MMU/OOM/native faults were zero, with one intentional validation fault. See `docs/evidence/vulkan-partial-buffer-optimal-pi4-20260930/README.md`. Other backends do not advertise this capability.
## Bounded partial optimal-to-optimal image copy

The Pi 4 backend implements at most one partial `vkCmdCopyImage` region per command buffer, between distinct, equal-size level-zero BGRA8 `UIF_NO_XOR` images. Source and destination offsets and width/height must align to 4×4 utiles, and the region is limited to 256 utiles. The shared command layer checks transfer usage/layout, extent bounds and disjoint allocations, then preflights the complete stream. The Pi 4 backend executes accepted regions using guarded 64-byte-utile DMA, selected by a dedicated tiled-rectangle capability; the existing full-image TFU path remains unchanged. The 2026-09-30 Pi 4 proof matched all 16 copied texels, preserved 240 untouched texels, and passed 64 padding and 96 guard checks. TFU stayed at 2, DMA advanced 0→1 and backend jobs 2→3; a later full readback advanced DMA 1→17. An unaligned request returned `-20005` without extra transfer work. See `docs/evidence/vulkan-partial-optimal-copy-pi4-20260930/README.md`. A separate staged Pi 4 silicon proof then passed at 64, 128 and the full 256 utiles, checking both complete 72×64 images, padding, guards and disjoint allocation ranges; see `docs/evidence/vulkan-optimal-optimal-aggregate-pi4-20261001/README.md`. Other board backends do not advertise this capability, so the shape is refused there.

## Extending the seam

A future board backend should implement the shared interface behind the same statically selected boundary, report only capabilities it can execute, and lower validated closed records into that board's own GPU operations. Add an operation or capability to the portable layer only with the corresponding backend contract and explicit unsupported behavior for backends that lack it. A future backend must not be inferred from shared Vulkan API coverage; it needs a named board implementation and its own hardware evidence.

The current shared slice remains bounded for future ports: it exposes one queue family and one shared allocation heap, and accepts only the implemented topology, source-over blend, and whole-pixel viewport forms. A new board must provide board-specific capability validation, hardware lowering, fault reporting, and silicon proof before any of those limits can be widened or support can be claimed.

## Ordered partial buffer-to-optimal uploads

The shared command layer accepts up to two separate one-region `vkCmdCopyBufferToImage` calls in one command buffer, targeting the same distinct optimal BGRA8 image. Source offsets are 64-byte aligned; row pitch may be tight or padded with the exact last-row span, and `bufferImageHeight` is validated. Destination offsets and extents align to 4×4 utiles. The calls must have disjoint destination rectangles and source byte spans, and their combined size is limited to 256 utiles. The complete stream is preflighted before backend work, then calls dispatch in recorded order. This Pi 4-only DMA path requires `BUFFER_TO_TILED_RECT_COPY`; other backends fail closed, and the full-image TFU path is unchanged. Desk checks prove a 257-tile aggregate is rejected without backend work. The earlier Pi 4 proof replaced 32 texels, preserved 224, and checked 288 source words including 48 padding words, 64 readback-padding words and 128 guard words. TFU stayed at 1, DMA advanced 0→2, and jobs 1→3; a later readback advanced DMA 2→18. A misaligned second operation was refused during recording with `-20005` before submit or DMA. See `docs/evidence/vulkan-two-partial-optimal-uploads-pi4-20260930/README.md`. The later 256-tile silicon proof is linked above.
The Pi 4 edge-tail extension passed: 25 texels changed, 196 valid texels and 291 padded UIF backing words outside the copy remained intact. Checks covered 246 source words, 54 source-padding words, 91 readback-padding words and 92 guards. TFU stayed at 1, DMA advanced 0→4 and jobs 1→2; later readback advanced DMA 4→24. A non-edge 5×5 request was refused during recording with `-20005` before more DMA. Submit-time malformed-stream preflight remains desk-only. See `docs/evidence/vulkan-optimal-upload-edge-tail-pi4-20260930/README.md`. A separate two-call Pi 4 proof used a 13×13 target: 17 texels changed, 152 valid texels remained unchanged, and 343 padded UIF backing words outside the copies were preserved. It checked 186 source words including 58 source-padding words, 39 readback-padding words and 112 guards. TFU stayed at 1, DMA advanced 0→2 and jobs 1→3; later readback advanced DMA 2→18. A non-edge second call returned `-20005` during recording before DMA. Submit-time malformed-second preflight is proven by signed desk regression only. See `docs/evidence/vulkan-optimal-upload-edge-tail-pi4-20260930/README.md` (`two-call-report.bin`). It keeps destination XY 4-aligned and permits short width/height only at the matching right/bottom image edge. Pi 4 lowers the final partial utile using clamped valid columns and rows, so guarded DMA writes only the copied texel bytes. It requires both `BUFFER_TO_TILED_RECT_COPY` and distinct `BUFFER_TO_TILED_TAIL_COPY`. The existing two-call limit, disjoint source/destination regions, and cumulative 256-tile ceiling use the sum of `ceil(width/4) * ceil(height/4)`. The exact source span remains `(height - 1) * pitch + width * 4`; row-skip bounds must account for the smallest tail row. The full command stream and per-tile source/destination ranges are preflighted before DMA. Full-image TFU remains unchanged; boards without both capabilities refuse the extension.
## One-utile micro buffer-to-optimal upload

A separate Pi 4 guarded-DMA capability accepts a 1–4 by 1–4 BGRA8 rectangle wholly contained in one 4×4 UIF utile, including an unaligned interior pixel origin, and writes only the requested bytes per row so surrounding utile texels are preserved. It requires both `BUFFER_TO_TILED_RECT_COPY` and `BUFFER_TO_TILED_MICRO_COPY`. The micro upload is isolated from other buffer-to-image operations in its command buffer. Source buffer offsets remain 64-byte aligned; the exact source span is `(height - 1) * pitch + width * 4`. Source/image aliasing, pitch/row skip, the containing 64-byte utile, allocation/window bounds and the full command stream are checked before DMA. Other boards do not advertise this capability and fail closed; full-image TFU uploads and the existing full-tile and edge-tail contracts are unchanged. The 2026-09-30 Pi 4 proof changed six requested texels and preserved 250, including ten same-utile neighbors; it checked 272 source words (262 payload and ten padding words), 64 readback-padding words and 96 guards. TFU stayed at 1, DMA advanced 0→1 and backend jobs 1→2. A crossing-utile request returned `-20005` during recording. MMU, OOM and native fault counts were zero. See `docs/evidence/vulkan-buffer-optimal-microrect-pi4-20260930/README.md`. Submit-time malformed-stream preflight remains desk-gate evidence.

### One-utile optimal-to-optimal microcopy

A separate Pi 4 capability copies one 1–4 by 1–4 BGRA8 rectangle between distinct equal-size level-zero optimal images. Source and destination offsets are independent; each rectangle must fit within one 4×4 UIF utile, and each image’s other texels are preserved. The route requires both `TILED_RECT_COPY` and dedicated `TILED_MICRO_COPY`; it is isolated as the sole copy/transfer/draw operation in its command buffer. Shared recording and submit validation recheck capability, resource/layout generations, extents and allocation aliasing before dispatch. Pi 4 lowers only the requested row bytes with guarded DMA at a 16-byte row stride; it does not use CPU pixels or TFU. Other backends fail closed. The 2026-09-30 proof changed four destination texels and preserved 252 (including twelve same-utile neighbors); all 256 source texels remained unchanged. Each readback checked 64 padding words and 128 guards. TFU stayed at 2, DMA advanced 0→1 and jobs 2→3; a source utile-crossing request returned `-20005` during recording. MMU, OOM and native fault counts were zero. See `docs/evidence/vulkan-optimal-optimal-microrect-pi4-20260930/README.md`. Submit-time malformed-stream preflight remains desk-gate evidence.

### One-utile optimal-image buffer readback

A separate Pi 4 DMA capability supports one interior `vkCmdCopyImageToBuffer` region of 1–4 by 1–4 BGRA8 texels, wholly inside one source 4×4 UIF utile. Destination offset remains four-byte aligned; tight or padded rows are checked against the exact last-row span `(height - 1) * pitch + width * 4`. The shared API requires both ordinary linear-transfer support and dedicated `TILED_MICRO_READBACK`; it rejects image/buffer aliasing and verifies capability, resource lifetime, bounds and destination stride before any DMA. The Pi 4 backend reads from the source's independent local UIF offset with guarded DMA; other backends fail closed. The 2026-10-01 proof matched four requested texel words, passed twelve row-padding checks, left all 256 source texels unchanged (including twelve same-utile neighbors), and passed 64 full-readback-padding, 16 stage-spare and 128 guard checks. TFU stayed at 1, DMA advanced 0→1 and jobs 1→2. A crossing-utile request returned `-20005` during recording; MMU, OOM and native faults were zero. See `docs/evidence/vulkan-optimal-buffer-microreadback-pi4-20261001/README.md`. Submit-time malformed-stream preflight remains desk-gate evidence. Other backends do not advertise this capability.

## Two-by-two UIF grid buffer upload

The shared buffer-to-image API supports one bounded interior optimal BGRA8 region spanning up to two adjacent UIF tile columns and two rows, under `BUFFER_TRANSFER`, `LINEAR_TRANSFER`, `BUFFER_TO_TILED_RECT_COPY`, and dedicated `BUFFER_TO_TILED_GRID_COPY`. It uses the buffer offset, pitch and exact source span from the recorded region, and preflights every tile intersection/window before DMA. Pi 4's guarded-DMA proof for `(3,3)` extent `5×5` measured four intersections (`1×1`, `4×1`, `1×4`, `4×4`), changed 25 texels, and preserved 231 including 39 neighbors within the touched grid. Source checks covered 25 exact words plus 327 sentinels (15 source-padding words); separate oracle padding and guards covered 64 and 96 words. TFU stayed at 1, DMA advanced 0→4 and jobs 1→2; later readback advanced DMA 4→20. The recorded `6×6` refusal was tested with only the original ≤2×2 grid cap, before the extended cap existed. With `BUFFER_TO_TILED_GRID_4X4_COPY` enabled, an otherwise-valid `6×6` region can be admitted; that exact size has not been silicon-tested. Submit-time malformed-stream preflight remains desk-only evidence. This capability is Pi 4-only; other backends fail closed and the full-image TFU path is unchanged. See `docs/evidence/vulkan-buffer-optimal-grid-pi4-20261001/README.md`.
