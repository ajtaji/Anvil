# Pi 4 optimal-image right-edge copy proof

The returning RAM diagnostic `RaspberryPi4/Examples/Diagnostics/vulkanOptimalToOptimalRightEdgeProof.pi4` copied one `5×4` BGRA8 rectangle from `(8,4)` in a 13×13 optimal image to `(8,8)` in a distinct 13×13 optimal image. The short width reaches the right edge; the height is one complete 4-texel tile. This tests different source and destination tile rows through public `vkCmdCopyImage`.

The 1,056-byte [`report.bin`](report.bin) has SHA-256 `B8B121A0578237D93DD3D0DB8B7571253A27C8AC3B7958703A22C21B343D9D5B`. All status, MMU, OOM and native-error slots are zero. The full destination oracle matched 20 copied and 149 untouched texels, including five untouched texels immediately below the rectangle. All 169 source texels remained unchanged. Staging checks matched 338 source words and 78 padding words; the two full-image readbacks each retained 91 padding words. The report also records 160 guard checks.

The initial images required two TFU jobs. During the partial copy, TFU stayed at 2, guarded DMA advanced 0→2 and backend jobs advanced 2→3. The destination and source oracle readbacks advanced DMA 2→18→34. A later nonedge request with source `(4,4)`, destination `(8,8)` and extent `5×4` returned `-20005` during recording without another DMA job. The one validation fault was intentional.

The signed PMFBOOT payload SHA-256 was `2C030EBE7FF59F6CD236CB352CA82CA2511AABE51EA730EA724D033C8EE606E7`. The source SHA-256 was `D9FCE7E27A379DF921A36C97608EC2001C6430A990E4E492C1EABA84972E3A89`; the independent checker `tools/vulkan_optimal_optimal_right_edge_proof_check.py` SHA-256 was `36148DEE065F8A1EB4D50518905812BD16BA6343EF03E5B47D9723EF57C54AC5`. `python tools/vulkan_optimal_optimal_right_edge_proof_check.py --report docs/evidence/vulkan-optimal-optimal-right-edge-pi4-20261001/report.bin` passes. This proves this bounded Pi 4 shape; the bottom-only `4×5` shape still has desk validation only. Other board backends remain fail-closed.
