# Pi 4 optimal-image bottom-edge copy proof

The returning RAM diagnostic `RaspberryPi4/Examples/Diagnostics/vulkanOptimalToOptimalBottomEdgeProof.pi4` copied one `4×5` BGRA8 rectangle from `(4,8)` in a 13×13 optimal image to `(8,8)` in a distinct 13×13 optimal image. The short height reaches the bottom edge; the width is one complete 4-texel tile. This tests different source and destination tile columns through public `vkCmdCopyImage`.

The 1,056-byte [`report.bin`](report.bin) has SHA-256 `E52AAB7AD6905E56EDACBD98A89DF2EBA4EC51467D5C39EBCDDB6DE48511F77D`. All status, MMU, OOM and native-error slots are zero. The full destination oracle matched 20 copied and 149 untouched texels, including five untouched texels immediately right of the rectangle. All 169 source texels remained unchanged. Staging checks matched 338 source words and 78 padding words; the two full-image readbacks each retained 91 padding words. The report also records 160 guard checks.

The initial images required two TFU jobs. During the partial copy, TFU stayed at 2, guarded DMA advanced 0→2 and backend jobs advanced 2→3. The destination and source oracle readbacks advanced DMA 2→18→34. A later nonedge request with source `(4,4)`, destination `(8,8)` and extent `4×5` returned `-20005` during recording without another DMA job. The one validation fault was intentional.

The Pi 4 RAM payload returned its report pointer in 1.3 seconds with a 15-second deadman; the resident Vulkan screen was restored. The signed PMFBOOT payload SHA-256 was `55FA8CF2107C1B240F54F3D2945F57D6CBA7BF804F82DC9855E329C7915B689B`. The source SHA-256 was `50BC37356FC7DBB830FA205016768778B13D95CFD1425F1C5024E554DDF94A8E`; the independent checker `tools/vulkan_optimal_optimal_bottom_edge_proof_check.py` SHA-256 was `1FD4A358161E1EB30767F1D4896E1C2F0192880E09C6324FBD747D63FC82A762`. `python tools/vulkan_optimal_optimal_bottom_edge_proof_check.py --report docs/evidence/vulkan-optimal-optimal-bottom-edge-pi4-20261001/report.bin` passes. This proves this bounded Pi 4 shape only; other board backends remain fail-closed.
