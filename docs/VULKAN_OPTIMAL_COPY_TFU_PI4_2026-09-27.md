# Pi 4 Vulkan optimal-image copy through the TFU — 2026-09-27

`vkCmdCopyImage` now accepts one complete level-zero BGRA8 region between two distinct, equal-size `UIF_NO_XOR` optimal images. It retains and validates both images and their allocations, refuses aliasing and unsupported regions before transfer, and submits one V3D texture formatting unit (TFU) job. The source image may be in `TRANSFER_SRC_OPTIMAL` or `GENERAL`; the destination may be in `TRANSFER_DST_OPTIMAL` or `GENERAL`. The copied destination becomes available to subsequent sampled draws after successful completion. Linear image copies continue to use guarded DMA.

The Pi 4 RAM diagnostic in `RaspberryPi4/Examples/Diagnostics/vulkanAtlasChromeProof.pi4` uploaded an 8×8 poison-padded atlas twice through the TFU, copied that optimal image to a second optimal image through the public `vkCmdCopyImage` entry point, and sampled the second image in eight V3D draws. The 960-byte report at `0x8308C8` returned status zero; its TFU counter advanced from zero to three, with the third job corresponding to the tiled copy. The final image layout was shader-read-only. The exact board report and rendered pixels passed 401 source, synthetic, report, and pixel checks with `tools/vulkan_atlas_chrome_acceptance_check.py --self-test`.

The corrected PMFBOOT v2 RAM payload was 1,126,128 bytes, SHA-256 `e18cc3979fceef02784abd56113334a32dc38e25bbfed2eb60fd816abdb00d3c`, linked at `0x600000`. The monitor verified the upload, returned `x0=0x8308C8` in about 10.3 seconds, and captured frame 63. Evidence is in `docs/evidence/vulkan-optimal-copy-20260927/`: `board-run.json`, `board-report.bin`, `board-capture.png`, and the logical 800×1280 BGRA capture compressed as `board-capture-800x1280.bgra.gz`. The preceding frame 62 exposed a shared image-format query that refused optimal `TRANSFER_SRC` at creation; the query was corrected before the passing run. Afterward the resident Vulkan console was restored, the deadman and capture were disarmed, and all coretest leases were zero. No flash, reset, or boot-medium write occurred.

The production Pi 4 path uses TFU registers for the tiled source and destination and waits for completion. CPU code records commands, validates bounds and layouts, and maintains cache visibility; it does not copy texels. The proof covers the stated whole-image shape. The full-image TFU route remains unchanged. A later implementation adds at most one bounded partial optimal-to-optimal region per command buffer, between distinct equal-size level-zero BGRA8 UIF images, with source/destination offsets and extents aligned to 4×4 utiles and a maximum of 256 utiles. The Pi 4 path executes that subset through guarded 64-byte-utile DMA behind a dedicated capability. The 2026-09-30 Pi 4 proof matched all 16 copied texels, preserved 240 untouched texels, and passed 64 padding and 96 guard checks. TFU stayed at 2, DMA advanced 0→1 and backend jobs 2→3; a later full readback advanced DMA 1→17. An unaligned request returned `-20005` without extra transfer work. See ``docs/evidence/vulkan-partial-optimal-copy-pi4-20260930/README.md`. Mip levels, array layers, format conversion, larger regions, and mixed render/transfer command jobs remain unsupported.

Desk validation on the corrected source: the isolated TFU checker passed 60 emitted checks over 50,790 AArch64 instructions; the production V3D backend checker passed 92 properties over 4,405,988 instructions; the public resource checker passed 724 properties over 6,707,022 instructions; and the full public pipeline gate passed 788 properties over 203,875,166 instructions. ### Bounded partial optimal-to-optimal edge-tail copy

The shared `vkCmdCopyImage` API supports one partial region per command buffer between distinct, equal-size level-zero BGRA8 `UIF_NO_XOR` images. Source and destination XY offsets remain 4-texel aligned. Width or height may end with a short UIF tile only when that dimension reaches the right or bottom edge in both images; the ceil-divided tile count is capped at 256. This shape requires `TILED_RECT_COPY` plus the separate `TILED_EDGE_TAIL_COPY` capability. Whole-image copies retain their TFU path, aligned full-utile rectangles retain the rectangle path, and one-utile microcopies retain their separate path. The Pi 4 backend preflights all clamped tile windows and performs guarded DMA for valid texel rows only, preserving source data, untouched destination texels and padded UIF storage. Other backends fail closed.

The 2026-10-01 Pi 4 proof copied a `(8,8)` `5×5` region between distinct 13×13 images: 25 destination texels changed, 144 stayed unchanged, and all 169 source texels were unchanged. The report checked 338 exact staging words plus 78 staging-padding words, 91 readback-padding words in each full readback, and 160 guard checks. TFU stayed at 2, partial DMA advanced 0→4 and jobs 2→3; the oracle readbacks advanced DMA 4→20→36. A non-edge `(4,4)` `5×5` request returned `-20005` during `vkEndCommandBuffer` before further DMA. Status slots were zero; MMU, OOM and native faults were zero, with one intentional validation fault. The measured trace is `docs/evidence/vulkan-optimal-optimal-edge-tail-pi4-20261001/report.bin`; the PMF SHA-256 is `8594C760D6E3206CFDC5DEAE41DBAAF6C0A770EDDA5FB5A369EBC3AA40ED027F`. Right-only `5×4` and bottom-only `4×5` cases have desk validation but no separate silicon proof.
