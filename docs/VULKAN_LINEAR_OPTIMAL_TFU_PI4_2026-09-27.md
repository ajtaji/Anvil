# Pi 4 Vulkan linear-to-optimal image copy through TFU — 2026-09-27

`vkCmdCopyImage` now accepts one complete level-zero BGRA8 region from a linear image into a distinct, equal-size optimal image. Both images require their Vulkan transfer usage and compatible transfer layouts. Recording rejects offsets, partial regions, overlap, incompatible shapes, and malformed source pitch. Submission revalidates the bound resources and the whole mapped source and padded destination ranges before starting TFU. The Pi 4 backend uses its existing raster-to-`UIF_NO_XOR` texture formatting path and waits for the hardware job; no CPU texel copy implements the Vulkan transfer.

The RAM diagnostic in `RaspberryPi4/Examples/Diagnostics/vulkanAtlasChromeProof.pi4` prepared an 8×8 linear atlas image from host fixture data, then copied that image through the public `vkCmdCopyImage` entry point into a newly allocated optimal image. Earlier in the same diagnostic, two buffer-to-optimal uploads and an optimal-to-optimal image copy ran, giving four TFU jobs total. The final descriptor sampled only the new linear-to-optimal destination in eight V3D draws. The 960-byte report at `0x8308C8` returned status zero, TFU jobs rose from zero to four, and the final image layout was shader-read-only. The report and rendered pixels passed 402 exact source, synthetic, board-report, and pixel checks.

The 1,133,068-byte PMFBOOT v2 payload, SHA-256 `b892836e5becfc11b59178ef85ed09101ef2ddb4222c1904276c962c8402502a`, was linked and verified at `0x600000`. It returned `x0=0x8308C8` in about 10.3 seconds and produced fresh capture 64. The report, capture, and run metadata are preserved in `docs/evidence/vulkan-linear-optimal-20260927/`. The resident Vulkan console was restored, deadman and capture were disarmed, all coretest leases were zero, and the board was released. No flash, reset, or boot-medium write occurred.

The TFU-supported operation remains one whole image. A separate partial linear-to-optimal path is implemented for one region per command buffer between distinct equal-size level-zero BGRA8 images: arbitrary in-bounds linear source offsets with actual-pitch validation, 4×4-utile-aligned destination offsets and extents, and at most 256 utiles. Pi 4 uses guarded DMA behind a dedicated capability for this shape. The 2026-09-30 Pi 4 proof copied 16 exact texels, preserved 240 untouched texels and matched all 256 source texels; 64 padding and 96 guard checks passed. TFU stayed at 1, DMA advanced 0→1 and backend jobs 1→2; a later readback advanced DMA 1→17. A misaligned destination returned `-20005` before readback. MMU, OOM and native fault counts were zero, with one intentional validation fault. See `docs/evidence/vulkan-partial-linear-optimal-pi4-20260930/README.md`. This does not change the complete-image TFU result, and other boards do not advertise the partial path. Layers, mip levels, format conversion, optimal-to-linear readback, and mixed render/transfer submissions remain outside the TFU path.
