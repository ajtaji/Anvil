A transfer-only command buffer can now interleave supported buffer copy, fill and update operations with supported buffer-to-image uploads and image-to-image copies. The queue revalidates all recorded buffer and image operations before submitting the first hardware job, then executes them in recording order. Pi 4 buffer operations use guarded DMA; complete optimal-image uploads and copies use TFU. A TFU job in a mixed stream must finish before the next operation begins. Render passes, image clears and image-to-buffer readbacks remain separate submissions.

The public diagnostic updated one staging-buffer texel from white to magenta using `vkCmdUpdateBuffer`, uploaded that buffer to an optimal atlas using `vkCmdCopyBufferToImage`, then copied the atlas to a fresh optimal image using `vkCmdCopyImage`, all in one command buffer. The eight-draw V3D scene sampled only the fresh destination. Its cyan-tinted toolbar became blue (`0xFF0000FF`), which requires the DMA update and both TFU jobs to occur in order. Six TFU jobs completed across the diagnostic. The final 960-byte report had zero status, settled fence and shader-read image layout, and capture 70 plus the report passed 405 exact source, synthetic, report and pixel checks.

The first new board run returned status 22 (`VVP_ERR_FENCE`) and `VK_ERROR_DEVICE_LOST` before its fifth TFU job. A diagnostic run showed `DmaReady() = 0`: this image-focused test had initialized DMA only after rendering, for display presentation. Moving its existing guarded DMA setup before the Vulkan transfer fixed the test; the final source also rebinds the display window for presentation. This was a test setup defect, not a CPU fallback. The failed runs are recorded as captures 67 and 68 in the board ledger.

The final 1,138,284-byte PMFBOOT v2 payload has SHA-256 `f53f7cea4be532afbdab70354863d9fb1b891463c96f90d13b131a0a741b76a8`. The Pi 4 verified it at `0x600000`, returned `x0=0x8308C8` after about 10.4 seconds, and produced capture 70. The report, capture, logical BGRA image and run metadata are preserved in `docs/evidence/vulkan-dma-tfu-stream-20260927/`. The Vulkan console was restored, deadman and capture disarmed, coretest leases zero, and the board released. This was a RAM-only run with no flash or boot-medium write.

The production V3D backend gate passed 92 checks over 4,405,988 interpreted AArch64 instructions. The normal Pi 4 image compiled at 4,344,312 bytes with its generated source stamp restored.
