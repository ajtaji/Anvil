# Optimal image-to-buffer readback on Pi 4

`vkCmdCopyImageToBuffer` accepts a complete level-zero BGRA8 optimal image and a bounded partial-region subset. The image must use the colour aspect, layer zero, transfer-source usage and `TRANSFER_SRC_OPTIMAL` or `GENERAL` layout. The destination buffer must have transfer-destination usage, a four-byte-aligned offset and enough space for tight or explicitly padded rows. Partial source offsets must align to the backend's 4×4 utile boundary; each extent must be a multiple of four unless it reaches that corresponding image edge. The full-image path accepts odd image extents. Recording and submission validate the operation before DMA. The Pi 4 backend detiles UIF_NO_XOR with guarded 2D DMA. The CPU configures DMA but does not copy pixels.

The resident Pi 4 at 192.168.1.111 ran the RAM payload from 0x700000 under a 15-second deadman. The 37x13 pattern crossed UIF block columns and padded-height rows. The payload first uploaded the image through TFU, then read it into a buffer with `bufferRowLength=41` and offset 8192. It returned `x0=0` after 2.6 seconds, compared all 481 BGRA words exactly, checked untouched row padding and counted 40 DMA operations with the channel quiescent. A 36x13 partial request returned `ANVIL_VK_ERR_UNSUPPORTED` at command-buffer end with no DMA. Capture 123 and the run record are in `docs/evidence/vulkan-optimal-image-buffer-20260927/`. The PMFBOOT container SHA-256 is `de6c822fb7036ed23dded1c342917f6aef25d4406b4d63ee7798f4023404d95b`.

Normal Pi 4 build 225 compiled at 4,378,096 bytes, raw SHA-256 `ad6c72e855bbce5e89f91c35619119c7634a4d7a5c279efb12c6b90d010b9d1d`. It was not installed. Build 223 remains resident; the Vulkan console was restored and the board lease released. No flash or reset was performed. The production backend gate passed 92 property checks. The public pipeline gate result is recorded in the compatibility status after it completes.

The bounded partial-region follow-up passed on Pi 4 in R2 on 2026-09-30. The exact trace is `docs/evidence/vulkan-partial-optimal-readback-20260930/report.bin`. The returning payload reported `x0=0x9408C8`; all scene statuses were zero; DMA advanced 0→1; all 16 requested texels matched; all 16 padding words and 32 guard words remained intact; an unaligned request was refused with `-20005`; TFU advanced 0→6 and bin/render counters 3→4; MMU, OOM and native-fault counters remained zero. This proves one bounded 4×4-aligned partial BGRA8 readback and its refusal path, not arbitrary regions. The 2026-09-27 37×13 full-image proof above remains separate evidence for odd full-image dimensions.

The 2026-09-30 R3 proof extends that subset to edge tails. Its trace is `docs/evidence/vulkan-optimal-edge-tail-pi4-20260930/report.bin` (1,056 bytes; SHA-256 `E6F23C73A931429506A2121103D3C72445EB46EF1383F9C4613FAE4548721D91`); the PMF SHA-256 is `5EE40B4904EC4AA72B9FA0DFF010CA80A9659A4C49F53D97A3E5444C066FF540`. The payload returned `x0=0x9488D0` in 8.4 seconds. On a 37×13 optimal image it uploaded via TFU (counter 0→1), then read `(32,8)` extent `5×5` into a padded buffer: all 25 texels matched, 15 padding words and 32 guard words remained intact, and DMA advanced 0→4. An inherited aligned-region check also passed; TFU advanced 1→7 and V3D bin/render advanced 3→4. A non-edge `(28,4)` `5×5` request was refused with `-20005` and no extra work. No faults were reported. This proves the tested right-and-bottom edge tail only; offsets still align to 4×4 utiles, and short extents must terminate at the corresponding edge. It does not establish aliasing or other-board support.
