# Optimal image-to-buffer readback on Pi 4

`vkCmdCopyImageToBuffer` accepts one complete level-zero BGRA8 optimal image with colour aspect, layer zero, transfer-source usage and `TRANSFER_SRC_OPTIMAL` or `GENERAL` layout. The destination buffer must have transfer-destination usage, a four-byte-aligned offset and enough space for tight or explicitly padded rows. Recording refuses partial optimal regions before any command is appended. Submission revalidates the buffer and image, including their allocations, before starting the ordered transfer stream. The Pi 4 backend detiles UIF_NO_XOR in 4x4 utiles using guarded 2D DMA. The CPU configures DMA but does not copy pixels.

The resident Pi 4 at 192.168.1.111 ran the RAM payload from 0x700000 under a 15-second deadman. The 37x13 pattern crossed UIF block columns and padded-height rows. The payload first uploaded the image through TFU, then read it into a buffer with `bufferRowLength=41` and offset 8192. It returned `x0=0` after 2.6 seconds, compared all 481 BGRA words exactly, checked untouched row padding and counted 40 DMA operations with the channel quiescent. A 36x13 partial request returned `ANVIL_VK_ERR_UNSUPPORTED` at command-buffer end with no DMA. Capture 123 and the run record are in `docs/evidence/vulkan-optimal-image-buffer-20260927/`. The PMFBOOT container SHA-256 is `de6c822fb7036ed23dded1c342917f6aef25d4406b4d63ee7798f4023404d95b`.
