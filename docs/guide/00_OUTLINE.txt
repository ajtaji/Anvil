; ======================================================================
; docs/guide/ - THE ANVIL GUIDE, the book.
;
; Files whose names start with 00_ are documentation OF the book and are
; never rendered. Every other .txt file in this folder is one chapter,
; read in filename order, so the leading number is the chapter order.
;
; WHAT THIS BOOK IS
;   The book somebody needs in order to build Anvil, put it on a
;   Raspberry Pi 4, talk to it, write a payload for it, run that payload
;   from a host machine, use all four cores, and replace the monitor
;   without losing the board.
;
;   It is not a replacement for docs/. The seventy-odd engineering notes
;   beside this folder are the record of HOW each piece came to work and
;   where its boundaries are; they are written for somebody who already
;   knows the machine. This book is the path IN. Chapter 11 is a map
;   back out to those notes, by topic.
;
; THE MARKUP
;   The house guide markup, unchanged, so the same renderer prints this
;   book and the shipped ones:
;
;     @CHAPTER <title>   starts a chapter. One per file.
;     @INTRO   <text>    one line under the chapter title. Optional.
;     @SECTION <title>   a heading inside the chapter.
;     <anything else>    a paragraph. A BLANK LINE starts a new one.
;     ; <text>           a comment. Never shown.
;     @CODE .. @ENDCODE  a COMPLETE, COMPILABLE program.
;     @FRAG .. @ENDFRAG  a fragment, a command line, or a transcript -
;                        shown as code, but not a whole program.
;     @TRAP <text>       a red callout: the mistake people actually make.
;     @NOTE <text>       a blue callout: worth knowing, not dangerous.
;
;   Inline **bold** and `code` work. A single blank line ends a
;   paragraph; nothing else does.
;
; THE RULES OF THIS BOOK
;   1. EVERY CLAIM IS TRUE TODAY. Not true in principle, not true once,
;      not true after the fix that is being written. Where something is
;      half done, the chapter says which half, in plain words, in the
;      place a reader would otherwise assume the whole.
;
;   2. EVERY COMMAND WAS RUN, OR IT IS QUOTED. A command line in this
;      book was either run on a desk machine while the book was written,
;      or it is reproduced exactly from the tool's own usage text or
;      from a recorded board session. Nothing is composed from what a
;      tool "probably" accepts.
;
;   3. "WHAT YOU WILL SEE" FOLLOWS EVERY COMMAND. A reader who types
;      something and gets output they cannot recognise has no way to
;      tell success from a partial failure. So the output is printed
;      too, as the board or the tool actually produced it. Where the
;      output came from a recorded board session rather than from a desk
;      run, the chapter says so on the spot - the words are "recorded
;      board session" - because a reader is entitled to know which
;      lines were watched and which were replayed.
;
;   4. TRANSCRIPTS ARE REDACTED, NOT REWRITTEN. Network names, hardware
;      addresses and machine-specific paths are replaced with obvious
;      placeholders. Nothing else in a quoted transcript is touched, and
;      no line is invented to fill a gap - a gap is described instead.
;
;   5. READING LEVEL: a working programmer who has not used this machine.
;      Short sentences. One new idea per paragraph. Every term gets one
;      plain-words definition the first time it appears, then gets used
;      normally. Second person throughout.
;
;   6. @TRAP is for mistakes that have actually been made, and most of
;      them have been made here. A trap invented to sound cautious
;      teaches nothing and costs the real ones their weight.
;
; CHAPTER PLAN - one file each, numbered
;   01_what_anvil_is        The resident monitor, the bootloader, the
;                           service table. What runs at which exception
;                           level. What a payload is; what a module is.
;   02_building_anvil       The compiler, PMF_COMPILER, tools/build.py,
;                           the build number, what lands in build/.
;   03_installing_on_a_pi4  Card layout, firmware files, config.txt, the
;                           EL3 stub, first boot, the serial console and
;                           the network console, version, map.
;   04_the_console          The commands people actually use, each with
;                           what it prints.
;   05_writing_a_payload    Placement flags, the service table, the
;                           deadman, what a payload must not do, and a
;                           complete small payload that returns a value.
;   06_running_from_the_host  board_run.py, anvil.py, upload with hash
;                           verification, readback, screenshots, and
;                           what a refusal looks like.
;   07_all_four_cores       The parallel service, partitions, bit
;                           identity, the bound, and the one-payload-
;                           per-boot limit that is still open.
;   08_updating_the_monitor In-place replacement, the two points after
;                           which you must not reset, recovery.
;   09_driver_modules       PMFMOD v1: the container, what exists, and
;                           the loader that does not.
;   10_proving_things       The gate set, the emitted-code interpreter,
;                           how to add a check, and why a listing is not
;                           proof.
;   11_the_engineering_notes  docs/, mapped by topic.
;   12_the_raspberry_pi_3   A/B slot content, the immutable loader and the
;                           Pi 3 memory facts.
;   13_truetype_t0          A memory-backed sfnt and first-TTC table
;                           directory reader with refusal diagnostics.
;   14_truetype_metrics     Bounded head/maxp/hhea/hmtx metrics and optional
;                           OS/2 fields, with an emitted gate and real fonts.
;   15_truetype_unicode     Bounded cmap format 4/12 mapping and strict
;                           UTF-8 decoding to glyph IDs.
;   16_truetype_outlines    Bounded loca/glyf simple and composite outline
;                           expansion to font-unit points.
;   17_truetype_raster      Four-by-four coverage rasterization and an
;                           independent fontTools outline oracle.
;   18_truetype_layout      GPOS/kern pair values, UTF-8 layout, and
;                           bounded emitted behavior checks.
;   19_truetype_console     Resident font commands, size and saved default
;                           path behavior, and bitmap fallback.
;   20_truetype_vulkan_runtime  Atlas cache behavior, resident Vulkan
;                           ownership and failure limits, and proof status.
