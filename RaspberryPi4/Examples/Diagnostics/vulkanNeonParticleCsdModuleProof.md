# Pi 4 opt-in particle producer diagnostics

These are returning RAM payloads for the Anvil-only `neon_vk_particle_csd.pi4` producer. They do not install a resident renderer. An operator must arm a **15-second deadman** before booting either payload and must keep sole board ownership until return or reset. Build with `--entry-returns --load-addr 8388608` and verify the PMFBOOT v2 load and entry are both `0x800000`. Use the monitor's reported `map` before upload; do not place the payload over a resident image. The report is 64 little-endian words (256 bytes) at the `global_ngpreport` symbol returned in `x0`.

The small proof uses 32 particles on a 128×128 offscreen target. Its Chrome shared vertex capacity is four quads while its external producer capacity is 32. It compares every one of the 192 generated six-word vertices with Chrome's CPU four-corner oracle, including unrotated and rotated/camera-transformed particles, verifies every output and input guard word, then checks 69 pixels. `vulkanNeonParticleCsdModuleProofCheck.py` checks the report. The Vulkan window is `0x063E8000..0x06FE8000` (12 MiB); the Neon surface is below it, starting `0x06000000`. The report distinguishes Chrome Create, module Create, Prepare/CSD, byte validation, Vulkan Begin/Draw/End, and final pixel verification. The output allocation is 12 KiB: 4608 live bytes, rounded to 8192, plus a 4096-byte guard page.

The 10,000-particle profile uses 625 groups of 16, a dedicated 1,445,888-byte output buffer, and a dedicated 487,424-byte input allocation. Chrome has one shared vertex quad; the external producer owns capacity for all 10,000 particles. It checks six selected records and all output/input guard words, then probes 20,000 pixels on an 800×800 target. `vulkanNeonParticleCsdModule10kProfileCheck.py` checks the report. The Vulkan window is `0x063E8000..0x073E8000` (16 MiB). Report words 19/20/43/48/61/62/49/40 hold palette, input staging, whole Prepare, CSD, sample-and-guard validation, draw recording, Vulkan End, and elapsed time through pixel checking in microseconds. This diagnostic is for an apples-to-apples timing comparison; it alone does not establish a production speedup.

Both payloads use the module's attach/quarantine contract. The module keeps Chrome attached while its buffer and pages exist, quarantines immediately before CSD submit, waits and checks clean/completion before clearing quarantine, and retains allocations on a sticky LOST result. Failed Vulkan idle or uncertain palette preparation also enters LOST and quarantines Chrome; a definite geometry argument refusal remains retryable. The payload never returns to the monitor if CSD, Vulkan submission, or idle state is uncertain: `ngpUnsafe` holds the payload in RAM until the armed deadman resets the board. The clean-return path waits for Vulkan idle, releases the producer, detaches Chrome, and only then destroys device resources. Setup, validation, draw, and pixel elapsed gates are 7, 10, 12, and 13 seconds respectively, leaving two seconds for clean teardown under the 15-second deadman.

For a production speed comparison, use a matched CPU and CSD profile pair with the same 10,000 records, 800×800 target, palette, Chrome draw and shared vertex capacities, Vulkan window, Begin/End path, pixel oracle, and idle boundary. Time Chrome Prepare, CPU `DrawPrepared` versus module input staging/CSD/`DrawExternal`, and End separately over several bounded frames, then compare total frame medians. The one-frame 10k diagnostic above is a correctness and phase-timing proof; the reduced shared-buffer configuration is a separate memory-capacity result.

From the repository root, compile either source with:

```
PureMetalForge.exe --compile RaspberryPi4/Examples/Diagnostics/vulkanNeonParticleCsdModuleProof.pi4 --entry-returns --load-addr 8388608 -o <output>.img
PureMetalForge.exe --compile RaspberryPi4/Examples/Diagnostics/vulkanNeonParticleCsdModule10kProfile.pi4 --entry-returns --load-addr 8388608 -o <output>.img
```

Use the generated `<output>.img.pmf` for supervised upload. Record the payload-specific SHA-256 and report address in the run manifest, since they change on rebuild. Desk checks are `python RaspberryPi4/Examples/Diagnostics/vulkanNeonParticleCsdModuleGate.py`, `python RaspberryPi4/Examples/Diagnostics/vulkanNeonParticleCsdModuleProofCheckTest.py`, and `python RaspberryPi4/Examples/Diagnostics/vulkanNeonParticleCsdModule10kProfileCheckTest.py`.
